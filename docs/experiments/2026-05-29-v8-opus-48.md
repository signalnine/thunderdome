# Opus 4.8 + v8 ablation ladder (2026-05-29)

## TL;DR

Three v8-prompt configs on Opus 4.8 via Claude Code OAuth (all using `--model opus` alias workaround for the CLI 2.1.154 thinking-block bug):

| Config | Overall | Standard | Hard | $/trial | n | Crashes |
|---|---:|---:|---:|---:|---:|---:|
| Vanilla 4.8 (baseline) | 83.9% | 81.8% | 87.0% | $1.33 | 37 | 2 |
| v8-no-review 4.8 | 82.4% | 81.2% | 84.1% | $1.30 | 37 | 4 |
| **v8-combined 4.8** | **85.8%** | **83.9%** | **88.5%** | **$1.29** | 37 | 4 |

**v8-combined is the winning 4.8 config** -- explicit review pass adds +1.9pp over vanilla and +3.4pp over no-review. Same pattern as 4.6 and 4.7: review does real work on this prompt structure.

**But all 4.8 configs sit -2.7pp below v8 + 4.6 (88.5%) and -2.8pp below v8-no-review + 4.6 (88.6%).** 4.6 with discipline remains the top mixed-suite config. Hard suite is where 4.8 is competitive; standard suite is where it falls behind.

**Cost is competitive**: $1.29/trial vs $1.49 for v8-combined-opus 4.6 and $5.46 for v8-combined-opus-47. The 76% drop vs 4.7 reflects the no-thinking workaround path.

## Methodology

n=2 full suite (19 tasks each), parallel=2, OAuth. Both sweeps use `--model opus` instead of `--model claude-opus-4-8` to dodge the CLI 2.1.154 thinking-block immutability bug documented in the [vanilla 4.8 writeup](2026-05-28-vanilla-opus-48.md). The alias resolves to 4.8 in `system.init` messages but the multi-turn loop appears to *not* enable extended thinking, so these are "4.8 no-thinking" numbers.

Two sweeps fired sequentially (parallel sweeps would compete on OAuth credentials):
- `conclave-v8-no-review-opus-48`: run dir `results/runs/2026-05-29T04-06-33/`, 3h08m wall clock
- `conclave-v8-combined-opus-48`: run dir `results/runs/2026-05-29T07-15-53/`, 2h48m wall clock

Both adapters were created by copying the corresponding `-47` adapter with `--model claude-opus-4-7` → `--model claude-opus-4-8`, then patched again post-vanilla-smoke to `--model opus` after the thinking-block bug surfaced.

## Three findings

**1. v8-combined is the right 4.8 config among these three, but doesn't beat 4.6.** v8-combined at 85.8% beats vanilla 4.8 (+1.9pp) and no-review 4.8 (+3.4pp). The explicit review step is doing real work on standard tasks, same pattern as previous models. But v8-combined-opus (4.6) at 88.5% still wins by 2.7pp overall. On hard suite alone the gap closes to -0.8pp (88.5% vs 89.3%), making 4.8 competitive on reasoning-heavy work.

**2. v8-no-review on 4.8 is a regression, opposite of 4.7.** On 4.7, removing the review pass *lifted* hard suite to 90.4% because hidden thinking substituted for explicit review (the central finding from the [4.7 no-review writeup](2026-05-22-no-review-opus-47.md)). On 4.8 with the alias workaround, no-thinking is forced -- so removing review removes work that *isn't* substituted, and hard suite drops to 84.1% (-3.4pp vs combined). This is direct evidence that the 4.8 alias path skips thinking: if it didn't, no-review should win hard suite same as on 4.7.

**3. Cost is the unambiguous 4.8 story.** All three 4.8 configs land at $1.29-$1.33/trial -- roughly 4.6 baseline cost ($1.18 vanilla, $1.49 v8-combined), and 38-76% below their 4.7 equivalents. v8-combined-48 at $1.29 vs v8-combined-47 at $5.46 is **-76% cost at -0.5pp accuracy**. If you were running v8-combined on 4.7 for the marginal hard-suite lift, switching to 4.8 + v8-combined keeps the same accuracy at one-quarter the cost.

## Bug + harness incidents

**Across both v8 sweeps: 8 thinking-block bug occurrences in 74 attempted trials (10.8%).** Significantly higher than vanilla 4.8 (3/38 = 7.9%) -- v8's longer sessions are more susceptible.

| Sweep | Bug rate | Crashes preserving scoreable work |
|---|---:|---:|
| no-review-48 | 4/37 = 10.8% | 3 of 4 |
| combined-48 | 4/37 = 10.8% | 3 of 4 |

Bug occurrences captured partial work in 6 of 8 cases (scored 0.26-0.91 from on-disk state at crash time). Only T10 ecommerce-backend trial-2 (no-review) and T2 collab-server trial-1 (one of them) crashed early enough to score near-zero.

**Harness `meta.json` missing on timeout**: T17 circuit-debugger trial-2 (combined-48) and T17 trial-1 (no-review-48) are missing meta.json after timeouts. Same pattern as vanilla 4.8 -- the runner does not write meta.json when a trial hits the wall-clock limit. Worth filing as a harness bug; means our n in these tables is 37 rather than 38.

**Cost outliers**: v8-combined-48 T19 trial-1 burned $5.25 in 27 min (bug crash, partial work scored 0.87). T19 trial-2 ran clean at $4.52 / 20 min. v8 review on T19 reasoning still hits the expensive long-tail seen on 4.7 + v8-combined-47.

## Recommendation

**For mixed standard+hard suites on bare Claude Code:**
- **Best 4.8 config**: `conclave-v8-combined-opus-48` at $1.29/trial, 85.8% overall.
- **Best overall**: `conclave-v8-no-review-opus` (4.6) at $1.28/trial, 88.6% overall -- still the leaderboard winner.
- **Practical default**: stay on the 4.6 v8 config until the CLI patch unblocks 4.8 + extended thinking.

**For hard-only sweeps on bare Claude Code:**
- 4.6 v8-no-review (89.9%) or 4.7 v8-no-review (90.4%) still beat 4.8 v8-combined (88.5%). Use the 4.7 no-review config -- it's the established hard specialist.

**For new exploratory work on 4.8:**
- Use `--model opus` alias, not explicit `claude-opus-4-8`.
- Expect ~10% trial loss to the thinking-block bug on v8-shaped prompts.
- File the harness `meta.json` on-timeout bug while debugging.

**When the CLI patch lands**: rerun all three 4.8 configs with explicit `claude-opus-4-8` to compare with-thinking vs no-thinking. The hard-suite delta is the experiment worth running -- if explicit thinking adds even +3pp to v8-combined-48's 88.5%, it crosses 91% and becomes leaderboard-competitive.
